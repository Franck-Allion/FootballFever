# Story 10.2: Hub Data Sanitization & Dynamic Calendar

Status: done

## Story

As a Manager,
I want the Hub to display accurate recent form, squad health, and upcoming fixtures from live game state,
so that I can trust the management screen when planning rotations and moving between the Hub, tactics, match, and main menu.

## Acceptance Criteria

1. New games start with an empty `streak` array in `useSquadStore`; no fabricated `W/D/L` history is shown before any match is finalized.
2. `routeNodes` are generated by code instead of using the current static demo array, with at least 5 nodes containing matches and rest periods and exactly one current node.
3. `teamName` and `teamLogo` remain store-driven and can be initialized or updated without hardcoded Hub-specific literals.
4. Hub averages for morale, stamina, fatigue, overall rating, and composites are derived from `roster`, `formation`, and assigned lineup state through existing rating services; the Hub must not fall back to mock values.
5. The Hub header includes an accessible icon button that navigates to `GameState.BOOT` through `FlowService`, with localized label/title text.
6. All user-visible Hub strings, aria labels, titles, status labels, and action tile text are localized through `useTranslation`; no hardcoded French or English text remains in `HubScreen.tsx`, `ProgressPanel.tsx`, or `ActionTile.tsx` call sites touched by this story.
7. Existing roster initialization, lineup assignment, tactics navigation, match navigation, and match-day finalization behavior continue to work.
8. Tests cover new-game sanitization, calendar generation, persisted-state migration/merge behavior, empty streak rendering, localized Hub labels, and BOOT navigation.
